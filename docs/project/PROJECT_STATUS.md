# 当前项目状态

更新日期：2026-11-10。

## 已完成功能

- 独立实验批次、状态重置、输入快照和策略状态隔离。
- 事件角度规划、初始评论池、每轮增量评论及分级兜底；初始舆论池支持
  `generate`（生成式）与 `harvest`（B 站采集式）两种来源。
- Persona读取、个人可见评论、Agent受约束LLM决策；历史模式生成原创表达，
  回应方案对照批次可自主选择沉默、原创或转发。
- Agent状态历史、个人评论历史、证据时间语义和公告草稿批次（`drafts`）。
- 共享进场前基线、官方动态进场、一组不回应基线和四个回应方案
  （`response_plan_1`～`response_plan_3` + `custom`）对照。
- Agent情绪、官方态度、过程效果、数据质量和性能指标。
- 单一历史趋势复现主线及其只读可视化；第2轮以后不注入真实评论或真实情绪比例。
- 历史 Agent 第一轮情绪由LLM初始化，后续情绪转移和官方态度由受证据约束的
  个体规则裁决；LLM负责解释、发言意愿和原创表达；不使用本地概率分层、
  人口配额或结果级群体坍缩熔断。
- 历史主对照使用 Agent 实际发表的评论；内部情绪和生成评论池作为分层诊断口径。
- 历史状态转换要求引用本轮新增证据，Persona依据、情绪依据和官方态度依据
  可单独审计。
- 历史已核实更新、客观事件和官方声明按背景/阶段进展/关键事实分级；缺少
  元数据的旧更新安全降级为阶段性证据。
- 同一证据会按Persona主题偏好、信息取向和上一轮情绪惯性分别计算情绪与
  官方态度影响，并在`evidence_appraisal`中保存实际引用证据的个体评估。
- 历史路径使用`persona_decision_v3 / personalized_hysteresis_v3 /
  emotion_transition_v1 / official_attitude_v3`。回应方案路径使用
  `strategy_directional_utility_v3`：证据按评论目标分流到事件情绪、官方态度
  和参与通道，权威证据按Persona处理速度在最多三轮内渐进吸收，实际推动一次
  变化后即停止重复作用；证据再与Persona先验、上一轮惯性和独立传播根共同
  形成唯一相邻状态。两条路径都保持情绪、官方态度和公开行为相互独立，
  不读取真实目标比例。
- 回应方案每轮外生LLM增量评论默认 8 条，历史复现仍为 20 条；实际配置随
  实验结果保存。
- 回应方案发言门控把“是否有新信息”拆为新鲜度、方向性证据相关度和状态效用
  张力；该门控不按正负情绪设置差别奖励。
- 官方态度已拆分为`claim_position`与`process_evaluation`；通告`clear`只表示
  表述清晰，不自动成为强证据。
- 每轮新增官方态度熵、最大群体占比、同步转向率和双维度分布诊断；诊断只
  记录现象，不终止或改写实验。
- 完整历史实验新增`run_manifest.json`，记录输入、核心代码、模型、温度、
  随机种子和实际Persona画像指纹，不记录API Key。
- 新官方通告拆成同一事实组下的可引用证据点，同一通告不会重复计为多条
  独立依据。
- 历史决策对静默时的多余表达、空派系和无通告时的空态度证据执行可审计
  规范化；发言决策缺少有效表达或派系仍会失败。
- 历史公众语境拆分为公共事实广播和个体讨论曝光；历史事件默认每名Agent
  关注5人，曝光目标为4条邻居表达和11条公共评论。
- 历史发言资格与内部状态分离；回应方案对照实现独立门控。
- 回应方案对照拆成纯状态判断、本地行为门控和按需原创表达三阶段；公开
  表达情绪开放三分类，原创表达有独立纠错重试和超长文本可审计句末裁剪。
- 固定社交网络、Agent影响力权重、邻居评论传播、公共评论补充和个人可见
  范围内最终表达；五个场景共享同一网络快照，进场后在各自状态目录独立演化。
- 邻居曝光事件、Agent表达谱系、传播层级和逐跳权重衰减；邻居池扩展到最近
  3 轮，按轮龄优先、根传播链去重和时间衰减抽样。
- 逐轮及场景级传播覆盖、继续传播、最大深度和有效权重指标。
- MongoDB 主存储：Persona、关系网络配置与快照、事件输入、事件状态；
  `data/backups/future_simulation.json` 为可提交的单文件备份。
- 知识图谱双存储：Neo4j 优先（HTTP Cypher / Aura Query API），
  `var/knowledge_graph/graph.json` 本地快照兜底；策略运行结束自动抽取新事件。
- JSON API：健康检查、输入默认值/预览、会话增删查与逐轮控制、报告状态/
  生成/PDF 下载、知识图谱；前端 Vue 3 控制台、历史、图谱、报告和设置页。
- 可视化保留历史复现、回应方案对照和共享网络三层；新控制台覆盖实时推演、
  会话历史、知识图谱和报告，历史复现页与方案对照横向视图仍由
  `legacy/visualization/` 提供。

## 暂缓与未完成功能

- 当前机制下的一次完整五场景 DeepSeek 批次尚未重跑；横向方案对比仍缺
  同批次数据。
- 多事件、多规模、多批次的统计稳定性仍需验证；现有完成批次以单场景为主，
  跑与跑之间的初始状态存在 LLM 随机差异。
- 任务队列、后台任务取消、多用户隔离和生产级并发调度未建设；长任务仍在
  HTTP 请求线程内同步执行。
- API 鉴权、限流、请求体大小限制和跨域配置未建设；当前只适合本机使用。
- 前端没有自动化测试和 lint；构建依赖 Node 20.19+，当前开发机 PATH 中没有
  `node`/`pnpm`，需要安装或显式设置 `NODE_EXE`。
- 动态关注关系、传播参数校准和固定官方回应时机对照实验未实施。
- 适应性画像和跨事件 Agent 长期更新暂缓。
- 数据库迁移脚本、schema 版本和实验结果的查询表尚未建设；实验产物仍以
  JSON/JSONL 为主。

## 当前主要风险

- 最新机制的同批次五场景完整实验缺失；引用 10/19、10/20 批次时必须标注
  “旧机制”，不能据此宣称 v3 的最终效果。
- 单场景完成批次的负面率曲线较平（如 10/28～11/05 的负面率全程基本不变），
  方案差异主要体现在官方态度/质疑率和表达结构，解释结果时不能把“情绪没变”
  误读为“公告无效”。
- 当前交付目录没有 `.git`，无法按 Git 历史核对版本来源；接手人应先确认
  版本来源，不要假设存在可回滚的提交。
- MongoDB、Neo4j 和 DeepSeek Key 都是外部依赖；Neo4j 不可用时只能使用本地
  快照，DeepSeek 未配置时只能浏览已有结果或使用规则摘要。
- `configs/neo4j.json` 里可能是本机凭据文件路径，提交前必须检查，不能把
  个人绝对路径或凭据带进共享仓库。
- 旧批次兼容测试依赖 `var/experiments` 中早期批次的网络快照文件；文件被
  清理后，legacy 的 1 项兼容性用例会失败，属于测试数据依赖，不代表页面
  服务不可用。
- `degraded` 表示某些轮次使用较多历史兜底，策略结果需要结合数据质量解释。
